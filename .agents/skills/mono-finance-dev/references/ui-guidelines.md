# UI guidelines

## Visual direction

Use an Apple-inspired, original visual language. Do not copy Apple assets or proprietary screens. The product should feel calm and information-dense without becoming decorative:

- rounded cards and controls;
- restrained glass or blur only where it improves hierarchy;
- strong spacing and large, legible typography;
- subtle shadows and smooth, purposeful motion;
- mobile-first layouts that expand efficiently on desktop;
- dark mode with accessible contrast.

## Financial interface rules

Use hierarchy to distinguish effective values from immutable originals. When a transaction has an adjustment, compensation, override, or exclusion, make the state clear without hiding its original imported value. Label converted and base-currency values distinctly from the original currency amount.

Provide loading, empty, error, and keyboard-accessible interaction states. Use semantic controls, visible focus states, readable chart alternatives, and responsive layouts. Avoid chart clutter and ensure displayed chart totals match the corresponding API values exactly.
